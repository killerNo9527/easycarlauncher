# 地图覆盖层实现说明 · SYSTEM_ALERT_WINDOW + TYPE_APPLICATION_OVERLAY

> 版本：`0.2.0-m2`（versionCode 2）· 2026-10-31
> 替代关系：本文取代 HANDOFF.md 第 4.4 节「地图区四条通道」中的**全部方案**。
> 代码：`app/src/main/java/com/lf/launcher/map/`

---

## 0. 一句话

地图卡不再把地图"塞进"布局，而是**在卡片矩形的屏幕位置上，放一个属于本应用的独立系统窗口**：
`WindowManager.addView(container, TYPE_APPLICATION_OVERLAY)`。
窗口里是我们自己的地图 View，视觉上"长在卡片里"，物理上是一个始终置顶、与桌面窗口互不隶属的悬浮层。

---

## 1. 方案边界（先划清楚，避免误解）

TYPE_APPLICATION_OVERLAY 窗口只能承载**本进程创建的 View**。它不能把别的应用（高德/百度车机版）的界面搬进来 ——
把别的 App 的活动渲染进自己的区域，只有 VirtualDisplay + `ActivityView`（需 `ADD_TRUSTED_DISPLAY` / `INJECT_EVENTS` 等系统签名权限或注入 system_server）才做得到。

所以本方案的分工是：

| 层 | 由谁渲染 | 说明 |
|---|---|---|
| **地图画面** | 本应用（`OverlayMapView`） | 现在画的是演示图层（路网/路线/定位点）；接地图 SDK 后换成 SDK 的 `MapView`，一行 `setMapContentView(view)` 即可 |
| **导航能力** | 地图 App 自己 | 点按地图区 → 全屏启动选定的地图应用 |
| **卡片位置/圆角/描边** | 覆盖层自己 | 系统窗口没有父布局可裁，圆角靠 `outlineProvider + clipToOutline` |

与文档旧方案的关系：

| 旧通道 | 结论 | 现在 |
|---|---|---|
| A 虚拟屏内嵌 | 需系统签名，普通安装必失败 | 已删除（`MapEmbedView` / `MapProbeActivity` / `MapWidgetClient`） |
| B 系统自由窗口 | 可用，但顶部长一条系统标题栏，且窗口独立于桌面 | 已删除（`FloatingMapLauncher` 的 freeform 通道） |
| C 悬浮条盖标题栏 | 只是给 B 打补丁 | 已删除（`MapHeaderOverlay`） |
| D 全屏打开导航 | 兜底 | **保留**，作为点按行为 |
| **E 覆盖层（本文）** | 新增 | `MapOverlayWindow` + `OverlayMapView` + `MapOverlayPermission` |

## 2. 权限申请：「显示在其他应用上层」

### 2.1 它是 appop，不是运行时权限

- 不能 `requestPermissions()`，也不能 `pm grant`（`pm grant` 只对 runtime permission 生效）；
- 读：`Settings.canDrawOverlays(context)`；
- 写：只能让用户在系统页面里点开关，或 `appops set <pkg> SYSTEM_ALERT_WINDOW allow`；
- **系统页没有回调**：用户点完开关返回，应用收不到任何结果 —— 只能在 `onResume` 里重新读一次。

### 2.2 四级降级（车机上这页经常被砍）

`MapOverlayPermission.request()`：

```
1. Settings.canDrawOverlays() == true              → GRANTED
2. 有 su 文件 → appops set <pkg> SYSTEM_ALERT_WINDOW allow → GRANTED_BY_ROOT
3. 有系统页 → ACTION_MANAGE_OVERLAY_PERMISSION(package:…) → OPENED_SETTINGS
4. 都没有   → 复制/展示 adb 命令                            → NEED_ADB
```

坑（沿用原工程实测）：

- 探测 root **只看 su 文件是否存在，绝不执行 su** —— 执行会弹 SuperSU 授权框，设置页刷新一次弹一次；
- manifest 里要声明 `ACCESS_SUPERUSER`，否则 SuperSU 报「未在 manifest 中定义」；
- targetSdk 28：`SYSTEM_ALERT_WINDOW` 仍需用户手动授予（高 targetSdk 上更严），停机在 28 是刻意选择。

### 2.3 用户可见的流程

```
未授权
  └─ 地图卡空态：图钉 + 「需要悬浮窗权限」+ 说明 + [去开启]
       └─ 点按 → 三步引导弹窗（打开设置页 / 找到「车载桌面」/ 回到桌面）
            ├─ [去开启]      → 跳系统页；返回桌面时 onResume 复检 → 自动挂载
            ├─ [复制 ADB 命令] → adb shell appops set com.lf.launcher SYSTEM_ALERT_WINDOW allow
            └─ [稍后]
```

代码：`MapOverlayPermission.showGuide()`；卡片状态机在 `HomeFragment.resolveState()`（`NO_APP / NEED_PERMISSION / READY / LAUNCH_ONLY`）。

## 3. 窗口创建

### 3.1 核心调用

```kotlin
val lp = WindowManager.LayoutParams(
    rect.width(), rect.height(),
    WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY,
    FLAG_NOT_FOCUSABLE or FLAG_NOT_TOUCHABLE or FLAG_NOT_TOUCH_MODAL
        or FLAG_LAYOUT_IN_SCREEN or FLAG_HARDWARE_ACCELERATED,
    PixelFormat.TRANSLUCENT,
).apply {
    gravity = Gravity.TOP or Gravity.START
    x = rect.left; y = rect.top
    windowAnimations = 0        // 车机上不要系统窗口动画，避免滑动时拖影
}
windowManager.addView(container, lp)
```

- **窗口类型**：API 26+ 用 `TYPE_APPLICATION_OVERLAY`（2038）；`TYPE_PHONE` 在 8.0+ 已被系统拒绝，代码里保留仅为低版本兼容。
- **坐标系**：`x/y` 是**屏幕坐标**，用 `View.getLocationOnScreen()` 取，不要用 `getLocationInWindow()`（Activity 窗口可能有偏移）。
- **透明**：`PixelFormat.TRANSLUCENT`，否则窗口底会变黑块。
- **圆角**：系统窗口没有父 ViewGroup，`clipToOutline` 是唯一办法：

```kotlin
view.outlineProvider = object : ViewOutlineProvider() {
    override fun getOutline(v: View, outline: Outline) =
        outline.setRoundRect(0, 0, v.width, v.height, cornerPx.toFloat())
}
view.clipToOutline = true
```

### 3.2 尺寸/位置同步

- 已挂载时只调 `updateViewLayout(view, lp)`，尺寸/位置没变直接 return，避免闪烁；
- 布局变化（状态栏显隐、卡片显隐、分辨率/密度变化）→ `HomeFragment` 的 `addOnLayoutChangeListener` → `syncMapOverlay()`；
- 改 flag（进入/退出交互模式）时**重建窗口**：部分 ROM 对 `updateViewLayout` 的 flag 变更不生效。

### 3.3 谁负责 show / hide

| 时机 | 动作 | 原因 |
|---|---|---|
| 首页可见且已授权 | `show()` | 正常态 |
| ViewPager 开始拖动 / 惯性滑动 | `hide()` | 窗口坐标是屏幕坐标，跟不上卡片位移 |
| 切到应用页（page != 0） | `hide()` | 只允许在首页地图卡区域出现 |
| Activity `onPause`（打开设置/选择器/系统授权页） | `hide()` | 覆盖层会压在我们自己的二级页面上 |
| 跳到其它应用、按 Home 到别处 | `hide()` | 系统窗口不随任务栈走，不收就会浮在别人头上 |
| 回到桌面 `onResume` | 复检权限 + `show()` | 系统授权页没有回调 |
| `onDestroyView` | `hide()` | 防止窗口泄漏 |

## 4. 焦点与任务管理：为什么是"分离"的

### 4.1 三条硬事实

| 事实 | 表现 | 处理 |
|---|---|---|
| **不在任务栈里** | 按 Home、进最近任务、Activity 重建都不会带走它 | 由 `LauncherWindowState` 显式驱动 show/hide |
| **不是 Activity 的子窗口** | 不受 Activity 窗口动画、裁剪、`View` 变换影响 | 位置/圆角/描边全部自己画 |
| **焦点独立** | 一旦可聚焦，桌面 `onWindowFocusChanged(false)`，沉浸式失效、系统栏冒出 | **本方案永不可聚焦**（见 4.2） |

### 4.2 焦点策略：只放触摸，不放焦点

| 模式 | flags | 效果 |
|---|---|---|
| 被动（默认） | `NOT_FOCUSABLE + NOT_TOUCHABLE` | 纯视觉层：桌面持有焦点，手指完全穿透，滑页/点卡片都正常 |
| 交互（设置里开） | `NOT_FOCUSABLE` | 触摸落在覆盖层（地图可拖动），**桌面仍持有焦点** |

为什么不给焦点：

1. 触摸事件不需要窗口聚焦，去掉 `FLAG_NOT_TOUCHABLE` 就够了；
2. 一旦可聚焦，桌面失去焦点 → `IMMERSIVE_STICKY` 失效 → 系统状态栏/导航栏立刻出现，车机上比"地图不能拖"更难看（实测截图已复现）；
3. 桌面持续持有焦点，遥控器方向键、语音唤醒、输入法都还归桌面，不会被这层截走。

代价（明确的取舍）：

- 交互模式下窗口收不到按键（DPAD / KEYCODE_*），要按键操作地图必须改成可聚焦模式；
- 若将来接了地图 SDK 且必须支持方向键，把 `setInteractive` 扩展成三态（穿透 / 触摸 / 聚焦触摸）即可，`LauncherActivity.onWindowFocusChanged` 里已预留 `isInteractive()` 判断，避免把自己的失焦误判成"切后台"。

### 4.3 实测证据（emulator 1920×1080 / API 28）

```
# 被动模式
fl=NOT_FOCUSABLE NOT_TOUCHABLE NOT_TOUCH_MODAL LAYOUT_IN_SCREEN HARDWARE_ACCELERATED
mAttrs={(28,67)(1428x971) ... ty=APPLICATION_OVERLAY fmt=TRANSLUCENT}
mCurrentFocus=Window{... com.lf.launcher/com.lf.launcher.LauncherActivity}

# 交互模式（设置里打开「覆盖层接收触摸」）
fl=NOT_FOCUSABLE NOT_TOUCH_MODAL LAYOUT_IN_SCREEN HARDWARE_ACCELERATED
mCurrentFocus=Window{... LauncherActivity}     ← 焦点仍在桌面
mResumedActivity=com.lf.launcher/.LauncherActivity
```

对照：如果切成可聚焦窗口，`mCurrentFocus` 会变成 `CarLauncher.MapOverlay`，同时系统栏出现。

## 5. 为什么不能"随桌面滑动/切页作为背景元素嵌入布局"

这是本方案的核心取舍，必须写清楚：

1. **坐标系不同**：覆盖层用屏幕坐标，ViewPager 滑动是 View 树内部的位移。窗口无法挂到任何 ViewGroup 上，也就无法"跟着卡片一起动"。
2. **跟手代价高**：真要在滑动过程中对齐，只能在 `onPageScrolled` 里每帧 `updateViewLayout` —— 会带来：
   - 与 ViewPager 的动画时钟不同步（窗口由 WMS 合成，View 由 App 的 RenderThread 绘制），必然出现 1~2 帧的错位/抖动；
   - 每帧跨进程调用 WMS，MT8666 上直接掉帧；
   - 滑动中途被系统裁剪/动画打断时还会闪。
3. **切页即错位**：滑到应用页后，卡片已经移出屏幕，但窗口还在原地 —— 如果不主动隐藏，就是"地图飘在应用列表上"。

因此采取的折中：

```
DRAGGING / SETTLING  → 立即 hide()（宁可闪一下，也不要拖影）
SETTLED 且 page == 0 → show() 并 updateViewLayout 对齐
```

视觉上表现为"滑动时地图消失、停稳后回来"。这是屏幕坐标窗口的固有代价，除非改成 VirtualDisplay 内嵌（要系统签名）。

其它可选路线与代价：

| 路线 | 能否真正"嵌进去" | 代价 |
|---|---|---|
| VirtualDisplay + ActivityView | 能 | 需系统签名/注入，普通安装必然失败 |
| 系统自由窗口 | 位置能对，内容不嵌 | 顶部长系统标题栏；地图窗口独立，切页不会跟着走 |
| PiP | 不能 | 用户可拖动、有系统边框，且同一时间只允许一个 PiP |
| **本方案（覆盖层）** | 位置/裁剪完全可控 | 不能跟随布局动画；只能显示本进程 View |

## 6. 只在首页地图卡区域显示

状态机在 `LauncherWindowState`（唯一事实来源）：

```
homeVisible = activityResumed && windowFocused && pageIndex == 0 && !pagerScrolling
```

四个触发点：

| 触发 | 调用 |
|---|---|
| `LauncherActivity.onResume` | `setPage(currentItem, false)` + `setResumed(true)` |
| `LauncherActivity.onPause` | `setResumed(false)` |
| `ViewPager2.onPageScrollStateChanged` | `setPage(currentItem, state != IDLE)` |
| `ViewPager2.onPageSelected` | `setPage(position, scrolling)` |

`HomeFragment` 监听该状态：`true → syncMapOverlay()`，`false → MapOverlayWindow.hide()`。
另有 `onStart/onResume` 与 `addOnLayoutChangeListener` 各兜一次，覆盖"从设置页返回""密度变化"等场景。

## 7. 已知限制 / 后续可做

| 项 | 现状 | 后续 |
|---|---|---|
| 地图画面 | 演示图层（Canvas 画的路网/路线/定位点） | 接地图 SDK 的 `MapView`：`MapOverlayWindow.setMapContent(view)` |
| 按键操作地图 | 不支持（窗口不可聚焦） | 需要时扩展为三态交互 |
| 滑动过程 | 隐藏，不做跟手 | 换 VirtualDisplay 内嵌才有意义 |
| 动画 | 硬切（`windowAnimations = 0`） | 若做淡入淡出，用 View 属性动画，不改窗口 flag |
| 车机 ROM 差异 | 个别 ROM 会拦截 `TYPE_APPLICATION_OVERLAY` | 失败时 `addView` 返回 false，卡片自动回落到「未授权」空态，不会白屏 |

## 8. 验证清单（emulator 1920×1080 / density 280 / API 28）

| 场景 | 结果 |
|---|---|
| 已授权进桌面 | 覆盖层挂载 `1428×971 @(28,67)`，与地图卡完全重合 |
| 滑动切到应用页 | 覆盖层移除，应用页无残留 |
| 滑回首页 | 覆盖层重新挂载并对齐 |
| 打开桌面设置 | 覆盖层移除（不压二级页） |
| 打开高德全屏 | 覆盖层移除（不压其它应用） |
| 按 Home 回桌面 | 覆盖层恢复 |
| 撤销权限重启 | 卡片显示「需要悬浮窗权限」+ [去开启] |
| 点 [去开启] | 引导弹窗 → 系统「显示在其他应用上层」页 |
| 授权后返回 | `onResume` 复检，自动挂载 |
| 交互模式 | 触摸被覆盖层接管，`mCurrentFocus` 仍是 LauncherActivity，系统栏不出现 |

不执行 `adb shell appops set com.lf.launcher SYSTEM_ALERT_WINDOW allow` 时，以上所有覆盖层行为都不会发生，桌面仍然可用（只是地图卡显示空态）。
