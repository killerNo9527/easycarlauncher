# 广播控制高德悬浮窗 —— 实现说明

> 协议来源：二次修改版高德（你提供的 `showMap()` / `hideMap()`）
> 代码：`map/AmapPlusController.kt` + `home/HomeFragment.kt` + `settings/SettingsSpec.kt`

## 一、协议

```java
// 显示
Intent i = new Intent("com.autonavi.plus.showmap");
i.putExtra("x", 0); i.putExtra("y", 0); i.putExtra("w", 0); i.putExtra("h", 0);
sendBroadcast(i);

// 隐藏
sendBroadcast(new Intent("com.autonavi.plus.closemap"));
```

前提说清楚：**这套只对二次修改包有效**。我拆过官方 `com.autonavi.amapauto` 9.1.0 的清单
（140 条 action）和 dex（`strings | grep 悬浮窗` = 0），两个 action 都不存在。
所以代码里**不会盲发**，先探测再决定。

## 二、三个关键设计

### 2.1 先探测，再发

```kotlin
// AmapPlusController.probe()
context.packageManager.queryBroadcastReceivers(Intent(ACTION_SHOW), 0)
```

`queryBroadcastReceivers` 能把「谁在清单里声明了 showmap 的接收者」查出来。
这是静态可查的，比盲发靠谱：

- 官方包 → 空列表 → 卡片直接显示「当前地图不认这套广播」，不让用户对着空气点；
- 修改包 → 返回包名 → 一切照常，而且 `setPackage()` 能精确投递
  （对方若提过 targetSdk，静态接收者就收不到隐式广播了，显式更稳）。

结果缓存，设置变更时 `invalidate()`。

### 2.2 强制发送开关（兜底）

如果修改包用的是**动态注册**的 receiver，`queryBroadcastReceivers` 查不到，
但广播其实仍能送达 —— 探测会误判成"不支持"。

所以设置里有一个「跳过广播探测，强制发送」：
打开后不看探测结果，直接发。两种情况都覆盖到。

### 2.3 坐标全传 0 开关

你给的示例代码 `x/y/w/h` 全传 0，说明那套实现可能**不读坐标**，位置由它自己记。

所以默认传卡片真实矩形（`mapRect(host)` 的屏幕绝对坐标），
设置里可以切成全传 0。哪个对，只能在你的车机上试出来。

## 三、生命周期绑定

```
首页可见（未滑动、有焦点）→ 发 showmap（带卡片矩形）
切到应用页 / 滑页 / 打开设置 / 跳其他应用 → 发 closemap
回到首页 → 重新算坐标再发一次 showmap
```

三个入口驱动，和覆盖层共用一套 `LauncherWindowState`：

| 时机 | 代码位置 |
|---|---|
| 布局变化 / 页面切回 | `HomeFragment.syncMapOverlay()` → `syncAmapPlus(host)` |
| 可见性变化 | `visibilityListener`（不可见时显式 `hide`） |
| Fragment 销毁 | `onDestroyView` |

⚠️ 这里踩过一个坑并已修：原先 `visibilityListener` 的 else 分支只收了覆盖层
（`MapOverlayWindow.hide()`），没管广播这一路，导致**切页时 closemap 根本不发**，
高德悬浮窗会留在应用列表上。现在三条收口都调了 `AmapPlusController.hide()`。

`hide()` 是幂等的（内部 `if (!shown) return`），重复调用不会刷屏。

## 四、实测记录（emulator-5554 / Android 9）

### 4.1 官方包：探测拦住了

切到「广播控制高德悬浮窗」模式后，卡片直接显示：

> **当前地图不认这套广播**
> 已探测：没有应用声明 `com.autonavi.plus.showmap` 的接收者。官方包不支持，只有二次修改版才行

logcat：

```
AmapPlus: probe → 无接收者（官方包不支持这套广播）
```

点按会跳到设置页换模式，不会卡在空卡片上。

### 4.2 开强制发送：链路跑通

```
AmapPlus: probe → 无接收者（官方包不支持这套广播）
AmapPlus: show rect=Rect(28, 67 - 1456, 1038) zero=false → null
```

`→ null` 表示没设 `setPackage`（强制模式下没有探测到的包名，走纯隐式广播）。

卡片显示「已请求高德显示悬浮窗」—— 这句是必要的：
**发出去 ≠ 画出来了**，我们没有任何办法知道对方有没有响应，
所以不能把空态全隐掉让卡片空成一片黑。

### 4.3 切页收放

```
首页 → show rect=Rect(28, 67 - 1456, 1038)
切到应用页 → hide
滑回首页 → show rect=Rect(28, 67 - 1456, 1038)
```

`Rect(28, 67 - 1456, 1038)` 就是 `map_host` 的屏幕绝对坐标（1920×1080 下）。

### 4.4 顺带修掉的一个真 bug

切到广播模式后，之前自由窗口拉起来的高德**还压在卡片位置上**（截图实证）。
原因是模式切换时只收了我们自己的覆盖层，没收拾自由窗口。
已加 `stopFreeform(ctx)`，任何非自由窗口模式都会先把它挪出可视区。

## 五、到你车上怎么验

1. 装上修改版高德，桌面 → 设置 → 地图 → **「showmap 广播探测」**，
   看它写的是「支持：com.xxx」还是「无接收者」；
2. 若写「无接收者」但确认装的是修改包 → 打开 **「跳过广播探测，强制发送」**；
3. 地图区显示方式选 **「广播控制高德悬浮窗」**；
4. 回桌面看高德悬浮窗有没有出现在地图卡位置；
5. 位置不对 → 打开 **「广播控制时坐标全传 0」** 再试；
6. 切到应用页，看它会不会自己消失（应该会，`closemap` 已发）。

## 六、失败排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 卡片显示「不认这套广播」 | 官方包，或修改包用动态注册 | 开「强制发送」 |
| 强制发送后仍无窗口 | 修改包要特定包名/签名才响应；或它要求更高权限 | 看对方 logcat |
| 窗口出现但位置不对 | 它不读 x/y/w/h，或读的 key 名不同 | 试「坐标全传 0」 |
| 切页不消失 | 对方不认 closemap | 只能用它自己的关闭逻辑，或让用户手动关 |
| 位置对但大小不对 | 它可能只认 w/h 中的某一个 | 需要在修改包里确认字段 |

## 七、这条路的固有边界

必须说清楚，因为它决定这个方案能走多远：

1. **窗口不归我们**。它是高德的系统窗口，不进我们的 View 树。
   页面切换、列表滚动、卡片重排，它都**不会跟着动**，只能靠我们发广播追。
2. **发出去不知道有没有生效**。`sendBroadcast` 不返回接收方状态，
   我们现在只能靠"卡上那行提示"和肉眼判断。
3. **行为随修改版变化**。它换个版本可能就改字段名、改语义，
   我们的代码没有编译期保证，只有运行时探测。

如果这三条里有任何一条不能接受，那答案还是之前的：**用地图 SDK 自己画**，
地图就是你的 View，从始至终在你的 View 树里。
