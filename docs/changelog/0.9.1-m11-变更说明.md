# 0.9.1-m11 变更说明 · 矮屏（改比例后）卡片溢出

> 构建 `0.9.1-m11`（versionCode 11）· 2026-11-01
> 触发场景：把模拟器从 1920×1080 改成 **1920×740 @240dpi**（1280×493dp）后，音乐卡只剩一条缝。

---

## 1. 现象与根因

1920×740 下右栏可用高度只有 **335dp**（= 493 − 38 状态栏 − 96 页面给底栏让位 − 24 列底边距）。
按标准档尺寸算，四张卡需要：

| 卡 | 需要 | 实际分到（weight） |
|---|---|---|
| 时间卡 | 68（固定高） | 68 |
| 音乐卡 | ≥ 200（封面 48 + 5 行歌词 + 进度） | ~150 |
| 行程卡 | ~100 | ~50 |
| 负载卡 | ~100 | ~50 |

**两条都是硬伤**：一是总需求（≈ 470dp）远超 335dp；二是音乐卡里 5 行歌词 + 48dp 封面 + 进度条
本身就有约 200dp 的下限，权重再分也变不出来。所以不是「字号大了一点」，是**这个高度装不下这份布局**。

顺带说明为什么之前的 `values-w1400dp` 档没兜住：它是**按宽度**分档，而换屏幕比例通常是
「宽度不变、高度变矮」，宽度档位完全感知不到。

---

## 2. 改法：按**高度**分档 + 结构降级

Android 限定符只有「最小高度」，没有「最大高度」，所以把默认档反过来了：

| 目录 | 生效条件 | 内容 |
|---|---|---|
| `values/` | 默认（< 600dp 高） | **紧凑档**（新写） |
| `values-h600dp/` | 可用高度 ≥ 600dp | 标准档（原来的 `values/` 整份搬过来） |
| `values-w1400dp/` | 宽 ≥ 1400dp | 大屏档（原有） |

> 1920dp 宽的大屏同时满足 `w1400dp` 和 `h600dp`，限定符优先级里 available **width 在 height 之前**，
> 所以大屏仍然走 `w1400dp`（已实测 2560×1080 仍是 5 行大字号）。

紧凑档做三件事：

1. **整体缩一档**：状态栏 38→32、卡片内边距 16/12→12/8、封面 48→40、值 17→14sp、歌词 15/19→12/15sp；
2. **收框架**：底栏 80→62dp、底栏离底 12→8dp、页面给底栏让位 96→74dp、列底边距 24→14dp
   （这几个原来是硬编码在布局里的，这版抽成 `bottom_bar_height` / `bottom_bar_margin_bottom` /
   `pager_bottom_inset` / `home_bottom_margin` 四个 dimen）；
3. **结构降级**：歌词 **5 行 → 3 行**。这是关键——只缩字号救不回来，5 行在这个高度每行只剩 10dp，
   字直接被裁，等于没有歌词。行数抽成 `@integer/lyric_lines`（3 / 5 / 5），
   `HomeFragment` 按它从 5 行里截中间那圈（当前句永远是索引 2，所以窗口是 `2±n`），隐藏的行不占高度。

三个档位的 `dimens.xml` 现在都是 **46 个同名键**（新增 4 个框架键），少一个就会回落到默认档，
以后加尺寸记得三份一起加。

---

## 3. 涉及文件

| 文件 | 改动 |
|---|---|
| `values/dimens.xml` | 重写为紧凑档（短屏默认） |
| `values-h600dp/dimens.xml` | **新建**：原 `values/` 整份（标准档）+ 4 个框架键 |
| `values-w1400dp/dimens.xml` | 补 4 个框架键 |
| `values/integers.xml` | **新建**：`lyric_lines = 3` |
| `values-h600dp/integers.xml`、`values-w1400dp/integers.xml` | **新建**：`lyric_lines = 5` |
| `layout/activity_launcher.xml` | `view_pager` marginBottom、`bottomBar` 高/底距改引用 dimen |
| `layout/fragment_home.xml` | 两处 `24dp` 底边距改 `@dimen/home_bottom_margin` |
| `home/HomeFragment.kt` | `LYRIC_IDS` 常量表；`applySettings()` 按 `@integer/lyric_lines` 截可见行 |
| `build.gradle.kts` | versionCode 11 / 0.9.1-m11 |

## 4. 实测（雷电 adbtest / 240dpi）

| 分辨率 | 命中档位 | 结果 |
|---|---|---|
| **1920×740**（493dp） | 紧凑 | 四卡全开也能放下：长时钟卡 + 音乐卡（封面/歌名/歌手/**3 行歌词含括号翻译**/进度）+ 行程三格 + 负载三格，无裁字 |
| 1920×740（用户自身配置：关时间卡/负载卡） | 紧凑 | 音乐卡更宽松，行程卡正常 |
| **1920×1080**（720dp） | 标准 | 与上一版完全一致：5 行歌词、80dp 底栏、大号时钟卡 |
| **2560×1080** | 大屏 | 5 行大字号，未被 h600dp 抢走 |
| 应用页 / 设置页 @740 | 紧凑/标准 | 图标 44dp、标签可读；设置页照常滚动 |

> 说明：测试时为了验证「最坏情况」我临时把四张卡都打开过，测完已把偏好还原成你原来的
> （`card_time=false`、`card_monitor=false`、`vehicle_power=false`、`map_auto_start=true`）。
> 现在矮屏四卡全开也没问题，想开随时开。
