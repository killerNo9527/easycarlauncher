# 0.9.7-m17 修滚动（扫不到句尾）+ 歌词行数按高度分 3 / 5 / 7 档

## 1. 滚动「只在能显示的那部分里晃」——根因是时间，不是宽度

上一版是**来回滚**：`32dp/s`，走一趟过去再走回来。问题出在时长和歌词停留时间的对比：

| 量 | 数值（1920×1080@160dpi 实测） |
|---|---|
| 歌词区可用宽度 | 374px |
| 长句实际宽度 | 655px（`Welcome Home, Son (Remastered)…`） |
| 需要滚动的距离 `travel` | 281px |
| 上一版滚一趟要多久 | 281 / 32 ≈ **8.8s** |
| 这句歌词实际停留多久 | **约 2~3s** |

也就是说：**没滚到句尾就换句了**，下一句又从偏移 0 开始 —— 每次只看到开头一小段，
表现就是「长歌词显示不全、滚动只在能显示的那部分里动」。日志能直接看到：

```
sweep start travel=281.0 moveMs=2554.5
sweep end   offset=149.852 travel=281.0   ← 扫到一半被换句打断
```

改法两层：

1. **单向，不来回**：开头停一下 → 一口气扫到句尾 → **停在句尾**等下一句。
   来回滚的第二趟本来就没时间走，去掉它反而把时间都留给「往前扫」。
2. **时长不写死，按这句的停留时间分配**：`HomeFragment` 用歌词时间轴算出
   `下一句起点 - 当前位置`，通过 `ScrollTextView.setSweepBudget(ms)` 传进来；
   控件把开头占 16%、其余全给扫描，保证**在换句之前扫完**。拿不到预算（最后一句）时退回按 110dp/s 估。

验证（日志 + 截帧）：

```
sweep start travel=250.0 moveMs=2272.7
sweep end   offset=250.0 travel=250.0   ← 扫满，停在句尾
```

停在句尾时截图是 `…t your fantasy play`（开头被切、句尾完整）+ 下方括号翻译，
连续 5 帧文字位置完全不变（确认没有回弹、没有反复抖）。

## 2. 歌词行数：3 / 5 / 7 按高度分档

原来是写死 5 行 + 按档隐藏（`lyric_line_0..4` 五个固定 id）。要加 7 行就得在 XML 里再摆两行、
代码里再维护一张 id 表，两头容易对不上。现在改成**按档生成**：

| 档位 | 行数 | 屏幕 |
|---|---|---|
| 紧凑 | **3** | `< 600dp` 高 |
| 标准 | **5** | `>= 600dp` 高 |
| 大屏 | **7** | `>= 1400dp` 宽（1920×1080@160dpi 这类） |

- `@integer/lyric_lines` 只放数字，行本身由 `HomeFragment.buildLyricRows()` 生成：
  奇数行、当前句恒在正中（`count / 2`）、其余行 weight 1、当前那格 weight 1.2（要放翻译）；
- 布局里的 `lyric_view` 变成空容器，不再写死任何行；
- 换档（改 density / 换屏导致 Activity 重建）时 `applySettings` 发现行数与资源不符会自动重建一次。

## 3. 验证

| 档位 | 模拟 | 结果 |
|---|---|---|
| 大屏（7 行）| 1920×1080 @160dpi | 上 3 / 当前 + 翻译 / 下 3，间距均匀，不压进度条 |
| 标准（5 行）| @240dpi | 上 2 / 当前 + 翻译 / 下 2 |
| 紧凑（3 行）| @320dpi | 上 1 / 当前 + 翻译 / 下 1 |

三档都是 `am force-stop` 冷启动后截图核对，0 崩溃；长句扫到句尾并停住，短句居中不动。
