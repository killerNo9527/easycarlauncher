# 0.9.3-m13 系统栏开关 + 全局四边留白

## 1. 需求

设置里要有「是否使用系统自带导航栏和状态栏」的开关；打开之后，再提供一个**全局四边 padding**
自定义入口，用来对齐车机上系统栏的真实占位。

## 2. 两种模式

| 模式 | systemUiVisibility | 内容位置 |
|---|---|---|
| 默认（独占整屏） | `LAYOUT_STABLE \| LAYOUT_FULLSCREEN \| LAYOUT_HIDE_NAVIGATION \| FULLSCREEN \| HIDE_NAVIGATION \| IMMERSIVE_STICKY` | 贴边，系统两条栏隐藏（和以前完全一致） |
| 使用系统栏 | 只保留 `LAYOUT_STABLE \| LAYOUT_FULLSCREEN \| LAYOUT_HIDE_NAVIGATION`（**只布局、不隐藏**） | 系统栏照常显示，内容按 `insets + 自定义留白` 让位 |

为什么用「布局到栏下面 + 手动补 padding」，而不是让系统把窗口缩到两条栏之间：

- 窗口一旦被系统缩，**壁纸就铺不满整屏**，状态栏后面会露出系统底色（黑/白），和桌面风格割裂；
- 车机系统栏高度经常报不准（有的把空调条算进 statusBar，有的导航栏高度恒 0），
  纯靠 insets 会「压住一点」或「空一大条」——必须留一个用户可调的偏置。

所以：**壁纸、遮罩仍在 root 层满屏；内容在 `content_root` 层按 insets + 用户留白内缩。**

## 3. 布局改动

`activity_launcher.xml` 新增一层内容容器：

```
root_view（壁纸 + scrim，满屏）
└─ content_root（padding 加在这一层）
   ├─ view_pager
   ├─ statusBar
   ├─ bottomBar
   └─ sidebarHost
```

壁纸和 scrim 留在外面，所以状态栏 / 导航栏后面也是满屏壁纸。

## 4. 新增设置

- **使用系统状态栏 / 导航栏**（`use_system_bars`，默认关）：外观分组，紧跟「显示底部导航」。
- **全局四边留白**（`pad_top/pad_bottom/pad_start/pad_end`，默认 0dp）：
  **只在开关打开后出现**；一行显示当前值「上x 下x 左x 右x」，点开是四根 SeekBar
  （上/下/左/右，0~96dp），拖动即时写入，另带「全部清零」。
  用滑杆而不是键盘：车机上打字最难用，留白又是个「边看边调」的量。

设置页本身也用同一套系统栏策略（`withCustomPadding = false`，只避让系统栏），
否则开了系统栏却把设置页关在一个没有系统导航栏的页面里。

## 5. 联动

- 桌面 `onResume` / `onWindowFocusChanged` 重新 `apply` 系统栏标志；
  从设置页返回时 `requestApplyInsets()` 重算 padding；
- 地图卡矩形会随 padding 变，`HomeFragment` 的布局监听照常重发 `showmap`，
  实测广播坐标 `Rect(24,52…)`（默认）→ `Rect(48,96…)`（系统栏 + 24/20dp 留白）跟着变。

## 6. 实测（1920×1080 / dpi 160 模拟器）

- 开关默认关：与 0.9.2-m12 完全一致（满屏、无系统栏）；
- 开关打开：系统状态栏出现，桌面内容整体下移；地图广播坐标同步变化；
- 四边留白 20/16/24/24：地图卡、右栏卡片、底栏同时内缩，四边留白均匀，无重叠、无裁切；
- 改回关闭 + 清零：立刻回到满屏独占（`Rect(24,52…)`）；
- 设置页顶部不再被系统状态栏压住；0 崩溃。

## 7. 已知

- 桌面自己的「时间 / 日期 / 瞬时功耗」与系统状态栏会同时存在（时间会显示两遍）。
  这是刻意的：用系统栏的车机通常想要系统的空调/音量控件，桌面那条可以在
  「显示顶部状态栏」里单独关掉。
- 系统导航栏在本模拟器上不显示（该镜像没有软导航栏），实车上会按 insets 正常避让。
