## 一、地图：只剩广播一条路，并且**实测跑通了**

### 删掉的方案

| 删除项 | 文件 |
|---|---|
| 悬浮覆盖层（自建 TYPE_APPLICATION_OVERLAY） | `map/MapOverlayWindow.kt`、`map/OverlayMapView.kt`、`map/MapOverlayPermission.kt` |
| 系统自由窗口 | `map/FreeformMapController.kt`、`map/FreeformFrameOverlay.kt` |
| 虚拟屏内嵌（ActivityView / VirtualDisplay） | `embed/EmbedCapability.kt`、`embed/VirtualDisplayHost.kt` |

清单同步清掉 `CAPTURE_VIDEO_OUTPUT`、`ADD_TRUSTED_DISPLAY`、`MANAGE_ACTIVITY_STACKS`、`INJECT_EVENTS`、`ACCESS_SUPERUSER`。

### 现在的实现

```
首页可见 → sendBroadcast(com.autonavi.plus.showmap, x/y/w/h)
切页 / 失焦 / 进设置 → sendBroadcast(com.autonavi.plus.closemap)
回首页 → 重新取卡片屏幕矩形再发一次
```

### 三条实测结论（其中两条推翻了我之前的判断）

**① 官方高德 9.1.0.600087 其实是认这套广播的。**

之前我在旧机器上得出"官方包不支持"，是因为只看了清单、只发了广播没等到窗口。这次的直接证据是 `dumpsys window windows`：

```
Window #1 Window{... u0 com.autonavi.amapauto}:
  mOwnerUid=10051 package=com.autonavi.amapauto appop=SYSTEM_ALERT_WINDOW
  mAttrs={(24,57)(1438x843) gr=TOP LEFT CENTER ty=APPLICATION_OVERLAY
    fl=NOT_FOCUSABLE NOT_TOUCH_MODAL LAYOUT_IN_SCREEN HARDWARE_ACCELERATED}
```

窗口是**高德自己建的**，位置尺寸正好是我们传过去的卡片矩形。所以不需要修改版，也不需要任何特权。

**② 接收者是运行时动态注册的，静态探测查不到。**

`cmd package query-receivers -a com.autonavi.plus.showmap` → `No receivers found`；
`queryBroadcastReceivers()` 同样为空。但广播真的送达了。

结论：**不能拿静态探测当门禁**。原实现里"探测不到就显示『不认这套广播』"会把能用的设备拦死。
现在改成：选了地图应用就直接发，探测结果只在界面上做说明。设置页里那条"跳过广播探测，强制发送"已删除。

**③ `w` / `h` 是右下角坐标，不是宽高。**

传 `(x=24, y=57, w=1438, h=843)` 得到的窗口是 `(24,57)(1414x786)`——
`1414 = 1438 - 24`、`786 = 843 - 57`，差值正好是 x/y。按矩形右下角理解就完全对上了。
实现里已改为传 `rect.right` / `rect.bottom`，现在窗口与卡片像素级贴合。

### 一个必须知道的限制：广播唤不醒没启动的高德

`force-stop com.autonavi.amapauto` 后再回桌面发 `showmap`：高德进程不会起来、窗口不会出现（`dumpsys` 里窗口数 0）。
也就是说**广播只能指挥"已经活着的"高德**。

界面上的处理：卡片保留一行可操作提示——

> 已请求 高德地图 显示悬浮窗 · 若未出现，请点按这里启动一次

地图正常显示时这行被浮窗盖住，看不到；没出来时它就是唯一线索，点卡片会全屏拉起导航。

### 交互与切换行为（实测）

| 场景 | 结果 |
|---|---|
| 首页可见 | 高德浮窗 `(24,57)(1438x843)`，与卡片完全重合 |
| 滑到应用页 | 发 `closemap`，窗口消失（`dumpsys` 计数 0，日志 `AmapPlus: hide`） |
| 滑回首页 | 重新 `show`，窗口回来（日志 `show rect=Rect(24, 57 - 1462, 900)`） |
| 点按地图区 | 触摸落进高德浮窗（`NOT_TOUCH_MODAL`），可直接拖动/缩放地图 |
| 从地图区起手滑动切页 | 不生效——触摸被高德吃掉，要从右侧卡片或底栏起手 |

## 二、音乐卡：5 行歌词、卡内不再放电控件

- 歌词区 5 行等分（`layout_height=0dp + weight=1`），**当前行固定落在正中间**（index = 2），前后各两句。
- 卡内原有的上一首 / 播放 / 下一首全部移除，卡里只剩：封面、歌名、歌手、5 行歌词、进度条。
- 歌词链路未变：`MediaMetadata.extras["lyricInfo"]` → 时间轴 → 按播放位置插值取行。
- 实测截图（《只若初见》）：瞬间也能是永远 / 用一生兑现那句誓言 / **只若初见**（高亮居中）/ 轮回千年与你相伴 / 少一秒都不圆满。
- 设置页里"歌词行数 4 行 / 2 行"的选择项已删除，改为说明项「固定 5 行 · 当前句居中，前后各两句」。

## 四、红心：与音乐应用双向同步

**读**：`readFavorite()` 按候选 key 依次探 `extras`：

```
is_favorite / isFavorite / favorite / favourite /
is_favourite / isCollected / is_collected / collect
```

支持 Boolean / Number / String；全都探不到时**沿用上一次的值**，避免每次刷新跳成未收藏。

**写**：点击走 `sendCustomCommand(SessionCommand("com.md3music.FAVORITE"))`，
参数带 `favorite` / `isFavorite`。**只有对方返回 `RESULT_SUCCESS` 才改 UI**，否则图标保持原状——
不会出现「点了变红心但其实没收藏」的假状态。

> 命令名 `com.md3music.FAVORITE` 是按包名推的约定值。若点红心没反应，说明播放器没注册这条命令，
> 换名字只改 `MusicController.CMD_FAVORITE` 一处。

## 五、修掉的崩溃（重要）

新机器上首次启动直接 FATAL：

```
java.lang.IllegalArgumentException: Failed to resolve SessionToken for
  ComponentInfo{com.md3music.md3music/...MD3MusicMediaSessionService}.
  Manifest doesn't declare one of either MediaSessionService, ...
  at com.lf.launcher.music.MusicController.start(MusicController.kt:114)
```

`SessionToken` 构造会校验目标 service 是否声明 Media3 能力，装了不兼容的音乐应用就会抛异常，
把整个桌面拖崩。已在 `start()` 里 `runCatching` 兜住并降级为"未连接播放器"状态。
