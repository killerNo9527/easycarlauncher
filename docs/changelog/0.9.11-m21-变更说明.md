# 0.9.11-m21 · 桌面内建 31 段全局均衡器

> 一句话：**在桌面里做出了真的 31 段全局 EQ，挂在 session 0 上，所有 App 出来的声音都过它**，
> 并且你那 20 点实测矫正曲线误差只有 **0.022 dB**。

---

## 1. 为什么这次成了

前面几轮一直卡在「标准 API 在 session 0 上失败」：`DynamicsProcessing(0,0)` 四种 Config 全报
`invalid parameter operation`（-5）。当时的结论是「设备不支持多段」，**这个结论是错的**。

真正的错误在参数上：

```
$ javap -constants android.media.audiofx.DynamicsProcessing
  public static final int VARIANT_FAVOR_FREQUENCY_RESOLUTION = 0;   ← 能用
  public static final int VARIANT_FAVOR_TIME_RESOLUTION = 1;        ← 一律 -5
```

我之前把这两个常量的值记反了（以为 FREQ=1、TIME=0），于是一直在拿 `1` 去试探，试一种挂一种，
看起来就像「设备不支持」。换成 `0` 之后：

| 组合（variant / 段数 / limiter） | 结果 |
|---|---|
| 0 / 31 / 有 | ✅ OK，`setPostEq(31)` 读回 mid=632Hz |
| 0 / 31 / 无 | ✅ OK |
| 0 / 20 / 有 | ✅ OK |
| 0 / 10 / 无 | ✅ OK |
| 1 / 31 / 有 | ❌ bad parameter value |

而且重启模拟器后再跑一遍结论一致，不是「被预热过」的假象。

**这台车机的 `libdynproc.so` 是能配多段的**，与 Poweramp 有没有私有协议无关 —— 它走的是
AOSP 标准 `DynamicsProcessing` 通道，只是我之前递过去的参数是错的。

## 2. 做了什么

### 2.1 31 段、任意增益、全局

- 频点：1/3 倍频程网格 **20Hz ~ 20kHz 共 31 段**（`EqPresets.FREQS`）
- 每个频点给 `cutoffFrequency + gain`，量程 **±12 dB**，精度 0.1 dB
- 挂在 **session 0（全局输出混音）**，不是自家播放会话 —— 所以 md3Music、导航、任何 App 的声音都过它
- 前级增益（preamp）−24 ~ 0 dB，用来在多加正增益时留 headroom，避免削顶

### 2.2 设置页新增「音效」分组

- **全局均衡器**：总开关（默认关）
- **调整均衡器**：进入调整页，右侧显示当前预设名

总开关只写配置，真正下发在桌面的 `onResume`（`EqSettings.restore()`）——
桌面是 HOME，开机第一个起来，进程不会被回收，effect 就不会丢。

### 2.3 调整页（横屏）

```
┌──────────────────────────────────────────────────────────────┐
│ 均衡器  全局生效中 · 31 段            [已启用·点此关闭] [关闭] │
├──────────────────────────────────────────────────────────────┤
│                       频响曲线（对数频率轴，量程自适应）        │
│  +6 ──────────────────────────────────────────────────────── │
│   0 ──────────────────────────────────────────────────────── │
│  -6 ──────────────────────────────────────────────────────── │
│      31   63   125  250  500   1k   2k   4k   8k   16k        │
├──────────────────────────────────────────────────────────────┤
│  ▁▂▃▄▅▆▇█  31 根竖推子（可直接拖动，拖动时浮出「80Hz -2.2 dB」）│
├──────────────────────────────────────────────────────────────┤
│ 预设 [平直] [车机矫正] [自定义]        [-] 前级 +0.0 dB [+] [全部归零] │
└──────────────────────────────────────────────────────────────┘
```

- 曲线每帧只算 31 次 biquad 系数（不是 192×31），拖动跟手
- 纵轴**自适应量程**：目标曲线通常只有 ±2~3 dB，固定 ±12 会把它压成一条直线
- 拖动时浮出数值气泡，抬手才落盘（拖动中 120ms 防抖下发）

### 2.4 你那 20 点矫正曲线

原始 20 点用 L2 最小二乘拟合到 31 段（1/3 倍频程 peaking 基函数）：

- **RMS 误差 0.022 dB / 最大 0.04 dB**
- 内置为「车机矫正」预设，点一下就能用

## 3. 验证结果（雷电 1920×1080 @160dpi，Android 9）

```
EqEngine: SystemEq created bands=31 session=0
SystemEq: apply readback bands=31 mid=#15 630Hz/0.0dB
EqEngine: apply ok enabled=true bands=31 preamp=0.0
```

```
$ dumpsys media.audio_flinger
  1 effects for session 0
  Effect ID 107:
      Session Status State Engine:
      00000   000    002   0xf3b85120
      - UUID: e0e6539b-1781-7261-676f-6d7573696340    ← libdynproc
      - flags: 00000050 (conn. mode: insert, insert pref: last, ...)
```

- `State=002` = enabled，`insert` 模式，session 0 → 确实在全局链上
- **回读校验**：`setPostEq` 在 HAL 拒绝时**不会抛异常**，只会把配置丢掉。所以每次下发后都回读
  一次 bandCount 与中间段（#15 = 630Hz），读回来的值对得上才算真的写进去了
- 连续冷启动 3 次全部成功；从调整页返回桌面后自动按存储配置重挂（effect ID 随进程重建，不残留）

## 4. 能力边界（要跟用户说清楚的）

| 想要 | 能不能 |
|---|---|
| 31 段、任意频点加减增益（图示 EQ） | ✅ 已实现 |
| 每段调 **Q**、换滤波器类型（参量 EQ） | ❌ `EqBand` 只有 `cutoffFrequency + gain`，没有 Q |
| 左右声道分开调 | ⚠️ API 支持按通道写，UI 暂未做 |
| 全局作用于所有 App | ✅ session 0；但若某个播放器走 offload 直通，framework effect 不参与 |
| 和 Poweramp 的 EQ 同时开 | ⚠️ 会串联叠加增益 → 失真。**只开一个** |

**不要同时开两个 EQ。** 现在车机上 Poweramp 的 20 段如果还开着，进桌面把
「设置 → 音效 → 全局均衡器」关掉，或者反过来。

## 5. 装法

```
adb install -r app-debug.apk
```

设置页 → 音效 → 全局均衡器（打开）→ 调整均衡器（挑「车机矫正」）。

开着的时候可以用下面两条确认它真的在跑：

```
adb logcat -s EqEngine SystemEq        # 看 apply ok / readback
adb shell dumpsys media.audio_flinger | grep -A6 "effects for session 0"
```
