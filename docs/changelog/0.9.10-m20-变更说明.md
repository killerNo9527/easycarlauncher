# 0.9.10-m20 删掉行程卡与状态栏瞬时功耗

## 1. 为什么要删

这两块数据都来自车辆总线，而这台车机上**读不到**：

- 标准 `android.car` 的属性服务没有暴露可用车况属性；
- 参照版本（`com.zzh.launcher50s.alpha`）走的是主机厂私有 binder（`CarServiceBinderPropertyClient`
  + `api_service_fallback`，propId `0x21405019` / `0x21405021` / `0x2160e003`），AIDL 经过加固拿不到。

结果就是常显 `--`：状态栏右上一直一个「⚡ -- kW」，行程卡三格全是 `--`。
与其留着当占位，不如删掉，把空间还回来。

## 2. 删了什么

| 位置 | 内容 |
|---|---|
| 状态栏 | `status_power` 整块（闪电图标 + 数值 + `kW` 单位）与前面那个 `Space` |
| 首页右栏 | `home_theme_classic.xml` 里的 `travel_card` include，以及 `include_travel_card.xml` 布局文件 |
| 首页代码 | `travelDistance / travelDuration / travelConsumption` 三个字段、`renderTrip()`、`formatDuration()`、`VehicleData` 订阅与 `travel_card` 显隐 |
| 设置页 | 「卡片」下的「行程卡」开关；**整个「车辆」分组**（瞬时功耗开关、车辆数据通道、vendor 属性实验开关、行程清零、打印车辆诊断） |
| 数据层 | 整个 `vehicle/` 包：`VehicleData.kt`、`CarPropertySource.kt`、`VehicleProbe.kt` |
| 资源 | `drawable/ic_bolt.xml`、`status_power_icon_size`（三档 dimens）、`card_travel_title`、`card_vehicle_unavailable`，以及配置键 `card_travel` / `vehicle_power` / `vehicle_vendor_power` |

保留**负载卡**：CPU / 内存 / 温度都是本机 `/proc` 能直接读到的，一直有数。

## 3. 布局上的连带变化

右栏从四张卡变三张，权重 `时间(96dp 固定) + 音乐 56 : 行程 19 : 负载 17` 变成 `音乐 56 : 负载 17`：

- 音乐卡的高度占比从 ~61% 涨到 ~77%，歌词区更宽裕（行数仍是 3 / 5 / 7 三档，按高度选）；
- 时间卡、负载卡关掉时音乐卡独占全高，不再有中间那段空档；
- `applyCardSpacing()` 仍按「第一张可见卡 topMargin = 0」处理，顶边对齐不受影响。

## 4. 验证

大屏档（1920×1080@160dpi）：

- 状态栏只剩「19:43 11月1日星期日」，右侧无图标无数字；
- 右栏依次为 时间卡（当前关闭）/ 音乐卡 / 负载卡，音乐卡 ~375px、负载卡 ~110px，比例 77 : 23；
- 冷启动无 `AndroidRuntime` 异常，切页正常。

## 5. 如果以后要把它们加回来

数据层是整包删的，重建的思路在 `0.9.8-m18` 之前的提交里：
`VehicleData`（1s 轮询 + 主线程回调 + 本次行程累计）→ `CarPropertySource`（反射
`CarPropertyManager`，只按属性名认，失败拉黑）→ `VehicleProbe`（诊断日志）。
前提还是同一个：**先确认这台车机的车辆通道能用什么方式读**，否则重建出来还是 `--`。
