# 0.8.0-m9 变更说明

音乐卡的视觉细化：封面缩小并裁圆、歌词层级与翻译、换行过渡动画。

---

## 一、封面：缩小 + 圆形

### 尺寸

原来 `album_cover` 是**卡片高的 26%**（约 100dp），比右边两行文字（歌名 18sp + 5dp + 歌手 13sp ≈ 41dp）
高出一倍多，顶部那一块看起来是「一小坨字贴在方图右上角」。

现在改成**固定边长**，只比这块文字大一点点：

| 档位 | 文字块 | `album_cover_size` |
|---|---|---|
| 默认（< 1400dp） | ≈ 41dp | **48dp** |
| w1400dp | ≈ 62dp | **68dp** |

`app/src/main/res/values/dimens.xml` / `values-w1400dp/dimens.xml`。
改 `music_title_text_size` / `music_artist_text_size` 时这张表要一起看。

### 圆形

原来靠 `ImageView + clipToOutline` + `bg_album_cover`（`shape="oval"`），**实测不裁**——
图还是方块（截图四角能看到图片像素）。原因是 `clipToOutline` 取的是 background 的 outline，
而本机 `GradientDrawable` 的 oval 并没有给出圆形 outline。

新增 `ui/CircleArtView.kt`：用 **BitmapShader + drawCircle** 画，形状由 `drawCircle` 决定，
不依赖任何 outline / clipPath（这条也在 m6 踩过坑：本机非凸 `clipPath` 裁完什么都不剩）。
缩放按 centerCrop 算（短边贴合、长边居中裁），圆外不留空。没有图时什么都不画，
露出 XML 里 `bg_album_cover` 的圆形渐变占位。

用在两处：
- 音乐卡 `album_art`（48dp 圆）
- 底栏 `bottom_art`（52dp 圆，也在 `activity_launcher.xml`）

`HomeFragment` 里 `albumCover` / `bottomArt` 字段类型改为 `CircleArtView`，
`setImageBitmap(...)` 换成 `setArt(...)`。

## 二、歌词

### 字号：当前行大一档，其它四行小一档

| 令牌 | 默认 | w1400dp |
|---|---|---|
| `lyric_current_text_size`（当前行） | 19sp | 27sp |
| `lyric_text_size`（其余四行） | 15sp | 21sp |
| `lyric_translation_text_size`（翻译） | 12sp | 16sp |

基准是原来的 17sp，当前行 +2、其余 -2（各一档），层级更明显。

### 居中

`styles_lyric.xml` 里 `android:gravity` 从 `center_vertical` 改成 `center`：
每行水平居中，垂直方向仍由 5 行等分自然居中。

### 当前行行高单独放大

`include_music_card.xml` 里 `lyric_line_2`（固定是当前行）`layout_weight` 从 1 改成 **1.5**：
这一行要同时放「歌词本体（长句会折行）+ 括号翻译」，等分行高会把它裁掉。
上下两侧仍是各 1，所以这一行的中心仍落在歌词区正中，视觉不偏。

### 换行过渡动画

`HomeFragment.animateLineSwap()`：当前句序号变化时，整个歌词块从下方 10dp、alpha 0.35
淡入上浮到位（240ms，`DecelerateInterpolator`）。
5 行是固定等分、文字整块替换，没有位移会「啪」地跳一下，加这个过渡看起来就是歌词向上滚了一行。

只在「当前句真的变了」时触发（`idx == lastLineIdx` 早退），150ms 的刷新循环不会反复重启动画。

### 翻译

**结论：md3Music 有翻译，能用。** 实测两首歌：

```
解析歌词：50 行（含翻译 46 行）… 首行=Marry You - Bruno Mars
解析歌词：71 行（含翻译 70 行）… 首行=なんでもないや (Movie ver.) - RADWIMPS
```

数据早就在 `lyricInfo` 里（解析器 `LyricInfoParser` 一直有 `translation` / `translationLyric` 两条 lane 的支持），
只是之前没渲染。现在的做法：

- 只给**当前行**拼第二行，`（翻译）` 用全角括号、`lyric_translation_text_size` 字号、`text_tertiary` 颜色；
  实现是 `SpannableString` + `AbsoluteSizeSpan` + `ForegroundColorSpan`（`HomeFragment.withTranslation()`）。
- 当前行 `maxLines`：有翻译 4 行（歌词折行 + 翻译折行），无翻译 2 行；其余行仍是 1 行。
- 那一句没有翻译时（版权行、纯音乐段）原样返回，**不出现空括号**，也不占额外行。
- 换歌时 `lastTimeline` 变化会作废缓存重绘，翻译跟着换。

日志里那句「含翻译 N 行」是常驻诊断，方便以后判断某首歌到底有没有翻译轨。

## 实测（Android 9 / 1920×1080，mdpi 1.5）

| 项 | 结果 |
|---|---|
| 封面 | 圆形，48dp，比「歌名+歌手」块高约 6~8px |
| 底栏封面 | 圆形，正常显示专辑图 |
| 歌词居中 | 五行均水平居中 |
| 字号 | 当前行 19sp，其余 15sp，差异明显 |
| 翻译 | `（我的宝贝 我只想和你结婚）`、`（哭过之后仰望的天空）` 紧贴当前行下方，无省略号 |
| 翻译折行 | 当前行折成两行 + 翻译时也不裁切（行高 weight 1.5 生效） |
| 过渡动画 | 抓帧捕到动画中间态（整块半透明、位置略低），确认生效 |
| 夜间模式 | 圆形封面 / 居中歌词 / 翻译配色都正常 |
| 切歌同步 | 连点三次「下一首」，界面与 `dumpsys media_session` 逐次一致 |
| 崩溃 | 0 |

## 已知遗留

1. **非当前行仍是单行省略**：英文长句会截成 `It's a beautiful night we're looking for …`。
   要完整显示只能给非当前行也开两行，但 5 行等分的观感会被打破，本次没动。
2. **歌名过长仍会省略**：「なんでもないや (没…」。卡片宽度固定，只能降字号或缩封面。
3. 封面 48dp 是「比文字块大几个 px」的取值，若后面调歌词/歌名字号，`album_cover_size` 要同步调。
