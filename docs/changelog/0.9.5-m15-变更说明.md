# 0.9.5-m15 清理设置里没有实际功能的选项

## 1. 判断标准

不是「看着多余」，而是**改了什么都不会发生**：

- 开关/选择项背后没有读取方（`Keys.XXX` 在代码里 0 引用）；
- 或者读到了也不影响任何绘制/行为；
- 或者只是把一句常量文字摆在那就没有交互。

按这个标准逐个 `grep` 了一遍，共删 6 行、3 个配置键。

## 2. 删掉的

| 行 | 为什么 |
|---|---|
| **桌面 · 开机自动启动** | 没有 `BOOT_COMPLETED` 接收者，`ready = false`，一直显示「待接入」 |
| **桌面 · 返回键回首页** | `LauncherActivity.onBackPressed` 本来就恒回首页，开关无读取方 |
| **音乐 · 封面旋转** | 全项目搜不到任何旋转动画实现 |
| **音乐 · 歌词行数** | 纯说明项，而且写的是「固定 5 行」——实际行数随屏幕档位变（矮屏 3 行 / 标准 5 行），是错的 |
| **地图 · 地图自启动** | 无读取方：`showmap` 本来就是随布局变化和回到前台自动发的 |
| **媒体 · 播放器** | 恒为字符串 `md3Music`，没有信息量 |

连带清掉的配置键（`SettingsStore`）：`AUTO_START`、`BACK_TO_HOME`、`MUSIC_VINYL`、
`LYRIC_LINES`、`MAP_AUTO_START`、`MAP_AMAP_PLUS_FORCE`（早已无引用）、`Defaults.LYRIC_LINES`。

「桌面」分组因此空了，整个分组标题一起删掉 —— 设置页现在从「外观」开始。

## 3. 顺手修掉一个会让开关「看起来坏了」的不一致

`显示底部导航` 在设置项里声明 `default = false`，但 `LauncherActivity.applySettings()`
读的时候用的是 `getBool(..., true)`。结果是：**全新安装 / 没动过这一项时，底部条带是显示着的，
开关却显示「关」**（点了才第一次写盘）。

统一为 `true`（条带默认显示），并重写描述：底部条带是「播放控制 + 首页/应用/设置入口」，
关掉后这些控件一起隐藏（设置仍可从应用列表进），页面会补回它占的高度。

## 4. 现在设置页还剩什么

全部有实际作用：

- **外观**：首页布局 / 昼夜模式 / 显示顶部状态栏 / 显示底部导航 / 使用系统状态栏导航栏 / 全局四边留白
- **卡片**：时间日期卡 / 音乐卡 / 行程卡 / 负载卡
- **车辆**：状态栏显示瞬时功耗 / 车辆数据通道（诊断结论）/ 实验（vendor 属性当功率）/ 行程清零 / 打印车辆诊断
- **音乐**：显示封面 / 显示歌词
- **地图**：当前地图 / 不绘制地图区边框 / 边框颜色
- **媒体**：连接状态 / 歌词行数（实时）/ 打开 md3Music
- **关于**：版本 / 屏幕 / 可用内存 / 系统

## 5. 验证

- 1920×1080 模拟器：设置页从头滚到底，只剩上面这些行，无空分组、无「待接入」；
- 底栏开关状态与实际显示一致；
- 桌面主页面前后对比无变化，0 崩溃。
