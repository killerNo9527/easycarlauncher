# 0.9.12-m22 · 双击输入数值 + 独立版均衡器

> 两件事：① 均衡器页支持**双击某一段直接输数值**；② 把同一套东西抽成**独立 App**，
> 可以直接装到别人机器上试（`CarEQ-1.1.apk`）。

---

## 1. 双击输入数值

### 为什么加

31 段挤在 1080px 里，一格只有 30 多像素；±12 dB 量程下 1px ≈ 0.14 dB。
想精确设成 −2.5 dB 这种值，靠拖根本对不准 —— 你手上那份矫正数据是 0.5 dB 粒度的，
拖是拖不出来的。

### 怎么用

**在某一段的推子上双击** → 弹出「80 Hz 增益 (dB)」→ 输数字 → 确定。

- 弹窗带 **归零** / 取消 / 确定 三个按钮，归零就是单独把这段清 0
- 输入范围钳在 ±12 dB，非法输入（字母、空）会提示而不改值
- 双击的第 1 下如果已经把那根推子拖动了，弹窗前会**把值撤回**，不会一边弹窗一边改曲线

### 实现要点

`EqEditorView` 里没用 `GestureDetector`（会和拖动抢事件），而是自己判：

```kotlin
// 抬手时：按下到抬起 < 220ms 且位移 < touchSlop → 算一次「点」
val tapped = event.eventTime - downAt < TAP_TIMEOUT_MS &&
    abs(event.x - downX) < touchSlop && abs(event.y - downY) < touchSlop
// 同一根推子、两次点间隔 < 340ms → 双击
if (prev == idx && event.eventTime - prevAt < DOUBLE_TAP_MS) { … onRequestInput(idx) }
```

### 顺带修的：弹窗配色

桌面有日夜两套配色，但均衡器页恒为深色。白天点开原本会弹一块白板，很跳。
现在固定用深色弹窗（`EqDialogTheme` + `bg_eq_dialog.xml`，圆角 + 描边），实测截图确认。

## 2. 独立版 CarEQ

### 它是什么

同一个 31 段引擎 + 同一套界面，抽成不依赖桌面的独立 APK：

- 包名 `com.lf.careq`，应用名「车载均衡器」，自带图标
- 工程是一个独立目录（**纯 Kotlin + Android framework，零第三方依赖**），现为单独的 CarEQ 仓库
- 交付文件 `CarEQ-1.1.apk`

### 和桌面版的关键差别：必须有前台服务

`AudioEffect` 绑在**创建它的进程**上，进程一被回收 effect 就销毁，声音立刻变回原样。
桌面版不需要担心（launcher 是 HOME，永远活着），独立 App 没有这个待遇。

所以加了 `EqService`：开着 EQ 时挂一条常驻通知（`IMPORTANCE_LOW`，不响不震），
服务活着 = effect 活着。关掉开关会立刻撤掉通知。这是普通 App 唯一合法的手段。

### 装法与使用

```
adb install -r CarEQ-1.1.apk
```

打开 → 点「点此启用」→ 挑预设或拖推子。切到别的音乐 App 依然生效（前台服务在跑）。

### 边界（照抄桌面版，一并说清楚）

| 项 | 说明 |
|---|---|
| 系统要求 | Android 9（API 28）及以上；没有 root 也能用 |
| 频段 | 31 段 1/3 倍频程，20Hz~20kHz，每段 ±12 dB，0.1 dB 精度 |
| Q 值 | **不能调**。`DynamicsProcessing.EqBand` 只有 cutoff + gain，这是图示 EQ 不是参量 EQ |
| 生效范围 | session 0（全局输出混音）。若某个播放器走 offload 直通，framework effect 不参与 |
| 保活 | 依赖前台服务；用户在系统里「强行停止」或清理后台把它杀了，EQ 就停了 |
| 与 Poweramp 同时开 | 会串联叠加增益导致失真，**只开一个** |

### 加的一处诊断

`SystemEq.setEnabled` 现在会回读并打日志：

```kotlin
Log.i("SystemEq", "setEnabled($on) readback=${dp.enabled}")
```

因为有的 ROM 上 `setEnabled` 不抛异常但 AudioFlinger 里仍是 DISABLED — 只有读回来才知道
到底开没开。这行日志以后能省掉「界面显示开着、耳朵没变化」的排查。

## 3. 两个版本同时装会打架

同一台机器上，桌面版和独立版**都在往 session 0 上挂 DynamicsProcessing**。
实测两边都能建起来、都报 `enabled=true`，但 `dumpsys` 里 session 0 只有一个 effect ——
也就是后挂的那个把前一个顶掉了。

**结论：只开一个。** 想让朋友试就单独装 CarEQ；想在桌面里调就关掉 CarEQ。
