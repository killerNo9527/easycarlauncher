# 0.9.6-m16 音乐卡字号放大 + 当前歌词改成横向滚动 + 底栏字号放大

## 1. 字号（三档一起放大）

以前的三档字号是按「5 行歌词塞进小卡片」定的，偏保守；这次整体上调约 15~20%，
并且把**底栏那两行从写死的 `15sp/11sp` 抽成 dimen**（原来三档共用一套值，矮屏会顶到条带上）。

| 项 | 紧凑档 `<600dp` | 标准档 `≥600dp` | 大屏档 `≥1400dp` |
|---|---|---|---|
| 歌名 | 15 → **17** | 18 → **22** | 28 → **32** |
| 歌手 | 11 → **13** | 13 → **15** | 21 → **23** |
| 歌词（非当前行） | 12 → **13** | 15 → **17** | 21 → **23** |
| 歌词（当前行） | 15 → **17** | 19 → **23** | 27 → **31** |
| 歌词翻译 | 10 → **11** | 12 → **13** | 16 → **17** |
| 卡片封面 | 40 → **44** | 48 → **56** | 68 → **80** |
| 底栏封面 | 52（写死）→ **46** | 52 → **58** | 52 → **70** |
| 底栏歌名 | 15（写死）→ **16** | 15 → **20** | 15 → **27** |
| 底栏歌手 | 11（写死）→ **12** | 11 → **15** | 11 → **20** |

大屏档的底栏高度 `80dp → 88dp`、页面让位 `96dp → 104dp`：27sp + 20sp 两行放进 80dp 会贴边。
封面维持「比歌名 + 歌手那两行略大一点」的比例，所以字号一动封面一起动。

## 2. 当前歌词：折行 → 横向滚动

场景：`Welcome Home, Son (Remastered) - Radical Face` 这类长句，中文歌里也有
「我感觉到你的拇指再次戳进我的皮肤」这种。原来的做法是 `maxLines` 折行，问题有三个：

1. 一折行就把那一格顶满，**下面的括号翻译被挤掉**（之前靠 `weight=1.5` + `maxLines=4` 硬撑）；
2. 五行歌词的节奏被破坏 —— 一格占两行高，视觉重心全歪；
3. 折行后的第二行读起来是「半句话」，跟着唱对不上。

改成**单行 + 超宽才横向来回滚**：

- 新增 `ui/ScrollTextView`：放得下就正常居中（大多数句子都在这一档，和普通 TextView 没区别），
  放不下才滚。滚动是 `canvas.translate`，不是 `scrollTo`（TextView 按 gravity 排版，
  位置在 layout 里定死，`scrollTo` 在部分机型上对它无效）。
- **不用系统 `ellipsize="marquee"`**：它只在 `isSelected` 时跑，被抢焦点/重新 attach 后经常静止，
  而且没有任何回调能知道它停了；它还是单向循环（滚到底直接跳回开头，中间不停），长句读起来是断的。
  自己实现的是「滚到头停一下，再反向滚回来」——一句读完正好回到开头。
- 速度 32dp/s（比系统 marquee 慢），两端各停 900ms。
- **播放暂停时滚动也停住并回到开头**：字还在动会让人以为没暂停。
- 非当前行仍是单行 + `ellipsize=end`（4 行都滚动会太吵）。

## 3. 翻译行拆成独立控件

原来翻译是拼进当前行的同一段 `Spannable`（`"$text\n（$tr）"` + `AbsoluteSizeSpan`）当第二行。
当前行变成单行滚动后，拼进去会被当成同一句一起滚走 —— 所以拆开：

```
lyric_current_box (weight 1.2)
├── lyric_line_2      ScrollTextView  当前歌词本体（单行滚动）
└── lyric_translation TextView        括号翻译（无翻译时 GONE，不占高度）
```

`GONE` 的好处：没有翻译时歌词本体自己撑满这一格，不会留一条空行。
格子权重从 `1.5` 收到 `1.2` —— 单行歌词不再需要那么高，收窄后当前行与上下行的间距也更均匀。

## 4. 验证

| 档位 | 怎么模拟 | 结果 |
|---|---|---|
| 大屏 `≥1400dp` | 1920×1080 @160dpi | 5 行 + 翻译完整；长句横向滚（实测 5 帧文字右边界 1863→1791→1721→1650→1586）；暂停后两帧完全静止 |
| 标准 `≥600dp` | 1920×1080 @240dpi | 5 行 + 翻译完整，字号明显大于旧版，底栏 20/15sp 不贴边 |
| 紧凑 `<600dp` | 1920×1080 @320dpi | 3 行 + 翻译完整，17sp 当前行可读，无裁切 |

三次都是 `am force-stop` 后冷启动 + 截图核对，0 崩溃。

顺带说明：`ScrollTextView` 在滚动时会持续 `invalidate`，`uiautomator dump` 会因为
「could not get idle state」失败（拿不到视图层级）。这是自动化测试工具的限制，
不影响桌面本身；要不是为了量字号我也不会用到它。
