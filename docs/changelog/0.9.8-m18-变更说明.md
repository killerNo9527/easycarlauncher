# 0.9.8-m18 长歌词：不再靠 TextView 排版，自己画

## 1. 车机上「中间被切一段、右边留白」是怎么来的

上一版溢出时用的是 `super.onDraw(canvas)` 外面套一层 `canvas.translate(-offset)`。看起来没问题，
但它画的到底是**什么**、画在**哪里**，完全由 TextView 内部的 Layout 决定：

- `getLayout().width` 是不是 `VERY_WIDE`（`setHorizontallyScrolling(true)` 有没有真的生效）；
- `ellipsize` 有没有被后续调用改回去；
- `gravity` 改了之后有没有重新排版；
- 以及它自己有没有再做一次裁剪。

模拟器上这套是齐的（`layoutW=1048576`），**车机上不齐** —— 结果就是一张「句子中间被切掉、
右边还留白」的窗口，也就是你拍到的那三张：`ey've finally come tru`、`hing everybo`、`d write`。

这些都不是「滚动距离算错了」，而是**画出来的东西和量出来的东西不是同一个坐标系**。

## 2. 改法：溢出时自己 `drawText`

```kotlin
val fm = paint.fontMetrics
val baseline = height / 2f - (fm.ascent + fm.descent) / 2f
canvas.save()
canvas.clipRect(0f, 0f, width.toFloat(), height.toFloat())
canvas.translate(-offset, 0f)
canvas.drawText(drawnText, 0f, baseline, paint)
canvas.restore()
```

关键在于：**测量和绘制用的是同一个 `paint`、同一个字符串**。`paint.measureText` 量多宽就画多宽，
平移多少就切掉多少，不再依赖任何 TextView 内部状态。放得下时仍走 `super.onDraw`（正常居中）。

顺带修掉三个连带问题：

| 问题 | 原因 | 处理 |
|---|---|---|
| 「差几个像素」的句子被拉成左对齐 + 微移 | 溢出判定只留了 1px 容差 | 溢出 < 6dp 一律当放得下 |
| 停到句尾时右边白出 30~40px | LRC 行尾有尾随空格，不显示但算进宽度 | 测量/绘制前 `trimEnd()` |
| 短句偶尔不居中 | 先设文本、后设字号 → `post{}` 里量的是旧字号 | 渲染顺序改成先 `styleLine()` 再 `text=` |

## 3. 滚动节奏：预算内的「往返」

上一版是「扫到句尾就停住」，问题是一句歌词只停三四秒，扫完剩下的时间全在显示句尾 ——
**抬头看一眼的人永远只看到半句话**（就是你拍到的形态）。所以改成在**这句的停留时间内往返一次**：

```
20% 看开头  →  33% 扫到句尾  →  20% 看句尾  →  27% 扫回开头
```

总时长 = 上一句起点到这一句的间隔（`HomeFragment` 从歌词时间轴算好，用 `setSweepBudget()` 下发），
夹在 1.2~8s 之间；拿不到（最后一句）兜底 5s。跑完停在开头，下一句正好接上。

## 4. 验证

- 大屏档（1920×1080@160dpi，7 行）：`But I do it in the best way` 整句可见（开头状态）；
  长句 `'Cause we could be Immortals` 出现「开头切掉、`Immortals` 完整贴在右边」的句尾状态 ——
  两态都在，说明窗口确实扫过了全句。
- 标准档（@240dpi，5 行）、紧凑档（@320dpi，3 行）：行数与间距不变，短句居中不受影响。
- 冷启动 0 崩溃。

## 5. 仍然存在的固有代价

单行滚动 = 任何时刻只能看到一句的一部分（要么开头、要么结尾）。这是「不折行」的代价，
与「整句一次看全」互斥。如果实车上仍觉得不好读，可选的两条路：

1. 字号再降一档，让更多句子直接放得下（放得下就完全不滚）；
2. 允许当前行折两行（翻译挤到下面），代价是五行/七行的节奏会被打破。
