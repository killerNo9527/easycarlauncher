# 0.9.9-m19 长歌词改成「扫到句尾就停」，并修掉同句被重复重扫

## 1. 去掉回程

上一版是「往返」：`20% 看开头 → 33% 扫到句尾 → 20% 看句尾 → 27% 扫回开头`。
你说不要再回到开头，关键帧直接砍掉回程段：

```kotlin
Keyframe.ofFloat(0f,           0f),     // 起点
Keyframe.ofFloat(0.20f,        0f),     // 停在开头 20%
Keyframe.ofFloat(0.50f,        dist),   // 30% 内扫到句尾
Keyframe.ofFloat(1f,           dist),   // 余下 50% 停在句尾
```

总时长仍等于「这句还能显示多久」（`setSweepBudget()` 从歌词时间轴算好下发），
所以扫完那一刻之后，字就稳稳停在句尾，直到下一句替换。

## 2. 但「回到开头」不全是回程造成的

加了 debug 日志抓了一段（75 秒 / 一首歌），第一次就抓到这样一组：

```
19:15:16.096  sweep start travel=267.0 budget=4497.0
19:15:16.098  sweep start travel=267.0 budget=4497.0   ← 隔 2ms 又来一次
```

同一句、同一个距离、同一个预算，2 毫秒内启动了两次 —— 也就是**扫到一半突然被拽回句首重扫**。
原因是 `restart()`（重新判定要不要滚、并把 offset 归零）有四个入口，全都会在换句的那一下同时触发：

| 入口 | 触发时机 |
|---|---|
| `setText()` 里的 `post {}` | 换句 |
| `onSizeChanged()` | 高度变化也算（翻译行出现 / 消失、行数档位变化） |
| `onVisibilityChanged()` | 歌词块显隐 |
| `onAttachedToWindow()` | 重新挂窗口 |

换句时这几个基本是一起响的，于是 offset 被反复清零。

**改法**：给判定加一个 key = `文本 | 可用宽度 | 字号`。key 没变就**直接返回，不碰进度**；
只有内容/宽度/字号真的变了才重新开始。

```kotlin
val key = "$content|$avail|${paint.textSize}"
if (key == lastKey) {
    if (pendingStart && canSweep()) { pendingStart = false; startAnimator() }
    return
}
```

配套两个细节：

- `pendingStart`：判定该滚、但当时暂停 / 不可见 / 还没 attach → 记下来，条件满足时补一次启动
  （否则 key 相同会被上面的 return 拦住，永远不滚）；
- `onAttachedToWindow` / `onVisibilityChanged(VISIBLE)` 里主动清 `lastKey` —— 离开窗口时动画被
  `stopAnimator()` 停掉了，回来必须重扫，不能当成「同一句，别动」。

## 3. 暂停不再把字归零

以前 `setScrollPaused(true)` 会把 offset 清零，恢复到 0 重扫 —— 读到一半被拽回句首，
跟这次要去掉的回程是同一种观感问题。改成 `ValueAnimator.pause()` / `resume()`（API 19+），
暂停停在哪，恢复就从哪接着走。

## 4. 验证

大屏档（1920×1080@160dpi，7 行），连播一首歌 75 秒，滚动了 15 次：

```
19:18:36.158  sweep start travel=258.0 budget=4645.0
19:18:40.828  sweep stop  offset=258.0 dist=258.0     ← 停在句尾，没有回程
19:18:41.133  sweep start travel=108.0 budget=4761.0
19:18:45.911  sweep stop  offset=108.0 dist=108.0
...
```

- 每次 `start` 后只有一次 `stop`，且 `offset == dist`（全部停在句尾）；
- 同一句不再出现重复 `start`；
- 动画时长与预算一致（4645ms 预算 → 4.67s 后结束）。

排查方法（debug 包才有输出）：

```
adb logcat -s ScrollTextView
```

## 5. 观察到但没动的现象

日志里有这么一小段：

```
19:19:23.727  sweep start travel=194.0 budget=4721.0
19:19:24.484  sweep start travel=255.0 budget=1200.0   ← 换到另一句
19:19:24.653  sweep start travel=194.0 budget=4692.0   ← 0.17s 后又跳回来
```

也就是歌词在**两句之间抖了一下**（索引 A→B→A）。这不是滚动逻辑，是 `HomeFragment` 取当前句
时在两句边界上被判了两次（播放位置在边界附近抖 0.1~0.2s 就会出现）。
观感是歌词块「跳一下 / 扫到一半重来」。需要的话可以加个小滞回：下一句起点没真正越过就不换句。
