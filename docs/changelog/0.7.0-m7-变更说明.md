# 0.7.0-m7 变更说明

构建：`app-debug.apk`（versionCode 7 / versionName 0.7.0-m7）· 2026-11-01
验证环境：雷电实例 `adbtest`（Android 9 / API 28 / 1920×1080 / dpi 240）
参考实现：`com.zzh.launcher50s.alpha`（反编译看到它用 `Theme.Material3.DayNight` +
`values-night` 色板，颜色成对出现，代码里没有配色分支）

## 一、界面跟随系统日夜切换

### 资源层：两套同名色板

| 文件 | 用途 |
|---|---|
| `values/colors.xml` | 日间（浅色） |
| `values-night/colors.xml` | 夜间（深色，原色板整体搬过来） |

两份**严格同名成对**，由系统按 `uiMode` 自动选择，配色代码里没有一处 `if (isNight)`。

主题父类从 `Theme.AppCompat.NoActionBar` 换成 `Theme.AppCompat.DayNight.NoActionBar`，
`windowLightStatusBar` / `windowLightNavigationBar` 用 `@bool/light_system_bars`
（日间 true、夜间 false），系统栏图标自动反色。

原来写死在 drawable 里的颜色全部改成色板引用，新增令牌：

```
wallpaper_top/center/bottom   壁纸渐变
wallpaper_scrim               壁纸蒙层（日 #26FFFFFF / 夜 #40000000）
map_card_top/center/bottom    地图卡底
bottom_bar_solid              底栏
cover_a / cover_b             无封面时的渐变占位
dialog_bg                     弹窗底
ctrl_bg / ctrl_bg_pressed     底栏按钮
chip_bg / chip_stroke         状态胶囊
icon_tint / icon_strong / icon_dim   图标
progress_track / switch_track 进度条、开关
```

（`ic_play` / `ic_pause` 保持纯白：它们只出现在蓝色播放圆钮上。）

### 控制层：三种模式

设置页「外观 → 昼夜模式」从「待接入」变成可用：

- **跟随系统**（默认）—— 系统切日夜，桌面实时跟着切；
- **日间 / 夜间** —— 强制固定，车机昼夜开关失灵或演示锁定用。

## 二、三个必须记下来的坑

### 1. 清单里的 `uiMode` 让系统不再重建 Activity

所有 Activity 都声明了 `...|uiMode|...` 的 `configChanges`（车机上防转屏/分辨率抖动重建桌面）。
代价是系统切日夜时**不会重建**，已 inflate 的 View 继续拿旧颜色。
→ 在 `ThemedActivity.onConfigurationChanged` 里比对 `uiMode` 是否真的变了，变了就 `recreate()`。

### 2. `AppCompatDelegate.setDefaultNightMode` 在这套 configChanges 下不生效

实测日志（同一时刻两条）：

```
Appearance: wrap mode=night night=true    ← 我们自己 createConfigurationContext 设的
Appearance: LauncherActivity onCreate mode=night night=false  ← 被 AppCompat 覆盖回去了
```

即：AppCompat 在 `attachBaseContext` 之后用自己的 override configuration 覆盖了 Resources。
→ 固定模式必须同时调 `Appearance.syncDelegate()`（`setDefaultNightMode`），
`attachBaseContext` 里的 uiMode 覆盖只作兜底。

### 3. `setMode` 里的「值没变就跳过」永远成立

设置页的适配器是**先写偏好、后回调**，回调里再读 `mode()` 一定等于刚选的值，
`if (mode() == value) return` 命中，界面永远不重建。
→ 判断挪到调用方（`SettingsActivity.modeAtBuild` 比对），`setMode` 里不再做这个短路。

## 三、状态一致性

| 状态 | 处理 |
|---|---|
| 当前页（首页 / 应用） | `onSaveInstanceState` 存 `viewPager.currentItem`，`onCreate` 恢复，不被日夜切换打回首页 |
| 音乐（歌名、封面、歌词、进度） | `MusicController` / 播放器连接都是单例，重建后 `renderMusic()` 立刻重绘 |
| 地图浮窗 + 圆角遮罩 | 随 `HomeFragment` 生命周期收放，重建后重新对齐矩形 |
| 设置页返回桌面 | `ThemedActivity.onResume` 比对模式，若在设置页改过则补一次重建 |

## 四、顺手修的两处

- 弹窗单选按钮原来是 AppCompat 默认**青色**（主题没指定 `colorAccent`），已改为品牌蓝 `#2F6FE0` / `#4C8DFF`。
- 地图圆角遮罩的 drawable 改为从 **Activity Context** 取：固定日间/夜间时 uiMode 覆盖只挂在它身上，
  用 `applicationContext` 会拿到系统那一套颜色，四角会和卡片对不上。

## 五、实测结果

| 场景 | 结果 |
|---|---|
| 系统日间（跟随系统） | 卡片 `(254,255,255)` 白、深色字、深色图标 |
| 系统切夜间 | 卡片 `(22,28,35)` 深色、浅色字，整屏实时切换 |
| 系统切回日间 | 回到 `(254,255,255)` |
| 在设置里选「夜间」（系统仍是日间） | 设置页立刻由 `(232,231,229)` 变 `(11,13,16)` |
| 在设置里选「日间」/「跟随系统」 | 同样即时生效 |
| 夜间切日间时停在应用页 | 仍停在应用页（页码被保存恢复） |
| 设置页被重建 | 仍在设置页，`mResumedActivity` 未跳走 |
| 地图卡四角 | 两种模式下圆弧与外圈描边都在，外侧填色与背景一致 |
| 崩溃 | 0 |

## 六、限制

1. 壁纸层用的是系统壁纸（`WallpaperManager`）。动态壁纸下，遮罩四角取色会随时间轻微不同步
   （静态壁纸、纯色壁纸都没问题）。
2. 日夜切换靠 `recreate()`，车机 MT8666 上会有一帧左右的重绘；不想看到这一帧的话，
   只能把首页所有卡片改成手动监听 uiMode 并逐层换色，代价是把配色逻辑从资源层搬进代码。
