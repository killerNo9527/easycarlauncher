# 0.9.13-m23 · 应用列表实时刷新

> 修一个真问题：**装完新应用不重启桌面就看不到它**。原因是应用列表只在页面创建时扫一次包名，
> 之后再没扫过 —— 而桌面是 HOME，可能几天都不重建。

---

## 1. 原因

`AppListFragment` 原来只有一处加载：

```kotlin
override fun onViewCreated(…) {
    …
    val apps = AppRepository.loadLaunchable(requireContext())   // ← 只在这里
    adapter.submit(listOf(settingsEntry) + apps)
}
```

`onViewCreated` 在 Fragment 视图创建时执行一次，之后**没有任何监听**。桌面是 HOME、常驻不重建，
所以那一份列表就是"启动时那一刻的快照"，新装的应用永远进不来。

## 2. 改法

### 2.1 监听包变化（前台即时生效）

```kotlin
private val packageReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context?, intent: Intent?) = scheduleRefresh()
}
```

`onStart` 注册、`onStop` 注销，IntentFilter 带四条 action + `package` data scheme：

```kotlin
addAction(Intent.ACTION_PACKAGE_ADDED)
addAction(Intent.ACTION_PACKAGE_REMOVED)
addAction(Intent.ACTION_PACKAGE_REPLACED)
addAction(Intent.ACTION_PACKAGE_CHANGED)
addDataScheme("package")     // ← 漏了这条一条广播都收不到
```

`PACKAGE_CHANGED` 是用来覆盖"应用被停用/启用"的 —— 现在 `AppRepository` 会过滤
`!activity.enabled`，所以停用后它应该从列表消失。

### 2.2 防抖 300ms

一次安装会连着来好几条广播（`ADDED` 带 `EXTRA_REPLACING` + `REPLACED`），
直接每次都重扫会做两三次无用功。用一个 `Handler` 的 `postDelayed(300ms)` 压掉。

### 2.3 回前台补扫

在后台期间，动态注册的接收者收不到广播（`onStop` 已注销）。所以 `onStart` 里除了注册，
还主动 `scheduleRefresh()` 一次：**装完应用从应用商店切回桌面，列表立刻是对的**，
不需要重启桌面。

### 2.4 顺手加的日志

```kotlin
Log.d("AppList", "reload count=${apps.size}")
```

`adb logcat -s AppList` 就能看到每次重扫的条目数，以后排查"列表少一个"很快。

## 3. 实测（雷电 Android 9）

| 操作 | 结果 |
|---|---|
| 停在应用列表页，`adb uninstall com.probe.eq` | 3 秒内图标消失，`reload count=11 → 10` |
| 停在应用列表页，`adb install` 同一个 APK | 4 秒内图标出现在正确位置，`reload count=10 → 11` |
| 先切到设置页（桌面进后台）再卸载，然后回到桌面 | 回桌面立刻 `reload count=10`，新状态正确 |

全程**没有重启桌面**。

## 4. 没做的

- `MapAppPickerActivity`（选地图应用那一页）仍然是进页面时扫一次。它是短生命周期页面、
  每次打开都重新创建，正常情况下不会看到旧数据；只有"在它开着的同时装应用"才会旧，不值当处理。
- 没有做增量 diff（按包名比对后 `notifyItemInserted`）。整表重扫 + `notifyDataSetChanged`
  在十几个应用下只要几十毫秒，而且不会因为排序变化出现插入动画错位。等应用数量真到几十个再说。
