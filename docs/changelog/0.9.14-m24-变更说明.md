# 0.9.14-m24 · 应用列表长按菜单（应用信息 / 卸载）

> 长按应用图标弹出菜单，和系统原生一致：用户装的给「应用信息 / 卸载」，
> 系统预装的只给「应用信息」。卸载走系统确认框，不自己删。

---

## 1. 做了什么

| 操作 | 结果 |
|---|---|
| 长按用户安装的应用 | 菜单：**应用信息** / **卸载**（橙色） |
| 长按系统预装应用 | 菜单：只有**应用信息** |
| 长按「桌面设置」（伪条目） | 不弹菜单 |
| 点「应用信息」 | 跳系统该应用的详情页（`InstalledAppDetails`） |
| 点「卸载」 | 弹系统卸载确认框，确认后真的卸载，列表自动消失 |

卸载完成后列表自动刷新 —— 靠的是上一版加的包广播监听（`PACKAGE_REMOVED`），
实测卸载后立刻 `reload count 10 → 9`，不需要重启桌面。

## 2. 为什么卸载必须靠系统

`Intent.ACTION_DELETE` + `package:xxx` 是唯一正确姿势：确认框由系统给，删除动作由
PackageInstaller 执行。桌面自己去 `pm uninstall` 需要系统签名，普通应用拿不到。

**这里踩了一个坑**，值得记：

```
E UninstallerActivity: Uid 10052 does not have
  android.permission.REQUEST_DELETE_PACKAGES or android.permission.DELETE_PACKAGES
```

第一版只写了 `startActivity(ACTION_DELETE)`，`startActivity` 不报错（所以 `runCatching`
里什么都抓不到），但系统卸载器把请求拒了 —— **界面上什么都不弹，看起来像菜单点了没反应**。
API 26 起，非系统应用发起卸载必须声明：

```xml
<uses-permission android:name="android.permission.REQUEST_DELETE_PACKAGES" />
```

它是 `normal` 权限，声明即得，不用运行时申请。加上之后立刻正常。

> 顺带说明为什么之前用 `adb shell am start -a android.intent.action.DELETE` 测是"通过"的：
> shell 用户（uid 2000）自带 `DELETE_PACKAGES`，所以那条命令绕过了这个限制，
> 把权限问题藏住了。测试手段本身也要挑对身份。

## 3. 实现要点

### 3.1 能不能卸载，由 `FLAG_SYSTEM` 决定

```kotlin
val flags = activity.applicationInfo?.flags ?: 0
val systemOnly = (flags and ApplicationInfo.FLAG_SYSTEM) != 0 &&
    (flags and ApplicationInfo.FLAG_UPDATED_SYSTEM_APP) == 0
canUninstall = !systemOnly
```

`FLAG_UPDATED_SYSTEM_APP`（系统应用的更新包）允许卸载 —— 那样是"回退到出厂版本"，
系统接受，所以不能一刀切按 `FLAG_SYSTEM` 藏掉。

### 3.2 菜单为什么自己画

没用 `PopupMenu`：它的字号跟主题走，在车机上偏小；而且列表格只有 140dp 宽，
系统 popup 的定位不好控制。这里固定 **190dp 宽 / 17sp / 每行 13dp 上下内边距**，
深色底 + 圆角描边（复用均衡器弹窗那套配色），浮在图标正下方居中。

PopupWindow 有两个必须给的：

```kotlin
PopupWindow(box, dp(190), WRAP_CONTENT, /* focusable = */ true)
setBackgroundDrawable(ColorDrawable(Color.TRANSPARENT))  // 不给的话 outside-touch 收不到，点外面关不掉
elevation = dp(10)                                        // 否则和下面的图标糊在一起
```

### 3.3 触感反馈

```kotlin
it.performHapticFeedback(HapticFeedbackConstants.LONG_PRESS)
```

车机上长按有没有生效很难判断（尤其菜单还没画出来的那一瞬），震一下最直接。

## 4. 实测（雷电 Android 9，1920×1080）

```
AppList: menu com.lf.careq canUninstall=true
AppList: menu com.android.settings canUninstall=false      ← 系统应用，只有「应用信息」
（长按「桌面设置」无任何日志、无菜单）

点「应用信息」→ mResumedActivity: com.android.settings/.applications.InstalledAppDetails
点「卸载」    → mResumedActivity: com.android.packageinstaller/.UninstallerActivity
              对话框「要卸载此应用吗？」→ 确定 → pm list 里包已消失
AppList: reload count=9                                     ← 列表自动更新
```

## 5. 没做的

- **强制停止 / 清除数据**：需要 `KILL_BACKGROUND_PROCESSES` 或系统权限，且「清除数据」
  对用户是破坏性操作。系统详情页里都有，长按菜单保持两项最干净。
- **拖拽换位置 / 添加到桌面**：应用列表是纯字母排序，没有自定义位置的概念，等真需要再做。
- 长按菜单宽 190dp 是写死的：应用名再长也只显示在菜单项里，不会撑宽。如果以后要放更多项
  （比如"固定到首页"），改成按最长文字测量宽度更合适。
